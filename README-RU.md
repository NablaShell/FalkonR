# FalkonR

`bak-cli` — encrypted directory archiver. Шифрует директорию в один vault-файл,
восстанавливает из vault'а, поддерживает **duress password** — второй пароль,
который при вводе уничтожает vault вместо распаковки.

Написан на Rust. Асинхронный I/O через `tokio`, параллельная обработка через
`rayon`, шифрование — `Argon2id` + `ChaCha20-Poly1305`, сжатие — `zstd`.

#@#
FalkonR --lock <dir>     запечатать директорию в vault
FalkonR --unlock <file>  восстановить vault
#@#

## Быстрый старт

Запечатать директорию:

#@#
FalkonR --lock ./mydir -o ./mydir.bak
Password:
Confirm:
Do you want use duress password? [y/N]: n
Chunk size: 1024 MB
Packing [████████████████████████████████] 100% 1.20 GiB/1.20 GiB (512 MiB/s)
Wiping source...
Done.
#@#

Восстановить:

#@#
FalkonR --unlock ./mydir.bak
Password:
Decrypting [████████████████████████████] 100% 1.20 GiB/1.20 GiB (396 MiB/s)
Restored: ./mydir
Done.
#@#

`--lock` после успешного создания vault'а **затирает исходную директорию**.
Это by design — иначе нет смысла в «запечатывании».

## Флаги командной строки

| Флаг | Алиас | Аргумент | По умолчанию | Описание |
|---|---|---|---|---|
| `--lock` | | `<DIR>` | — | Директория для запечатывания |
| `--unlock` | | `<FILE>` | — | Vault-файл для распаковки |
| `--output` | `-o` | `<PATH>` | `vault.bak` | Путь выходного vault'а |
| `--duress` | | `<PASSWORD>` | — | Аварийный duress-пароль (устаревший, см. ниже) |
| `--verbose` | `-v` | — | `false` | Подробный вывод |
| `--help` | `-h` | — | — | Справка |

`--lock` и `--unlock` взаимоисключающие.

## Duress password

Duress — это **второй пароль** к тому же vault'у. Вводишь его при `--unlock` —
программа предлагает уничтожить vault вместо распаковки. Задумано на случай
принуждения: если у тебя требуют пароль под давлением, ты вводишь duress,
и vault самоуничтожается.

### Как задать

При `--lock` после ввода основного пароля:

#@#
Password:            <основной пароль>
Confirm:             <основной пароль>
Do you want use duress password? [y/N]: y
Duress password:     <duress-пароль>
Confirm duress:      <duress-пароль>
#@#

Требования:
- duress-пароль **не должен совпадать** с основным;
- duress-пароль задаётся только при создании vault'а, потом его не поменять;
- если ответить `n` (или просто Enter) — vault создаётся без duress-слота.

### Как использовать

#@#
FalkonR --unlock ./mydir.bak
Password:            <duress-пароль>
Duress password detected. Destroy vault? [y/N]: y
Vault destroyed.
Done.
#@#

Если ответить `n` — vault остаётся на месте, распаковка не происходит.

### Почему это безопаснее `--duress <argv>`

Флаг `--duress <PASSWORD>` из старой версии **не использовался для хранения
duress в vault'е**. Он сравнивал введённый пароль со строкой из `argv`, что:

- светит duress-пароль в `ps`, `/proc/<pid>/cmdline`, истории shell;
- бесполезно, если vault унесли на другую машину без этого флага;
- не даёт никакой криптографической защиты.

В FalkonR duress-пароль **не хранится в открытом виде**. Он используется
для шифрования отдельного слота внутри vault'а (см. ниже). Проверка
«это duress или нет» — это **успешная расшифровка** duress-слота, а не
сравнение строк.

## Как это работает

1. `--lock` сканирует директорию (параллельно, через `rayon` + `walkdir`).
2. Строит внутренний поток: заголовок + для каждого файла `[len][path][size][content]`.
3. Сжимает поток `zstd`.
4. Шифрует `ChaCha20-Poly1305` чанками по `chunk_size` (по умолчанию — ¼ свободной RAM, от 16 MiB до 1 GiB).
5. Оборачивает в слот: `[salt][slot_len][ciphertext]`.
6. Если задан duress — повторяет 2–5 с **маркером** `\x00\x00DURESS\x00\x00` вместо реального архива и **другим паролем**.
7. Пишет контейнер: `[header][slot 0][slot 1?]`.
8. Затирает исходную директорию.

`--unlock` делает обратное, но с перебором слотов: для каждого слота
деривит ключ из введённого пароля и пробует расшифровать первый чанк.
Первый слот, который расшифровался — «наш». Если это duress-слот →
предлагает wipe. Если real-слот → распаковывает. Если ни один не подошёл →
`wrong password`.

## Формат vault-файла

### Общая структура

#@#
┌─────────────────────────────────────────────┐
│ Container Header (8 bytes)                  │
├─────────────────────────────────────────────┤
│ Slot 0  (real)                              │
│   ├── salt         (16 bytes)               │
│   ├── slot_len     (8 bytes, BE u64)        │
│   └── slot_body    (slot_len bytes)         │
├─────────────────────────────────────────────┤
│ Slot 1  (duress, optional)                  │
│   ├── salt         (16 bytes)               │
│   ├── slot_len     (8 bytes, BE u64)        │
│   └── slot_body    (slot_len bytes)         │
└─────────────────────────────────────────────┘
#@#

**Почему `slot_len` критичен.** Без него нельзя понять, где кончается
slot 0 и начинается slot 1. С `slot_len` можно перебирать слоты: не подошёл
ключ к slot 0 — переходим к slot 1, и т.д. Без `slot_len` пришлось бы
читать всё последовательно и падать на первом же неверном ключе.

**Почему `salt` лежит рядом со слотом, а не в общем заголовке.** Каждый
слот имеет свой salt → свой ключ. Основной пароль и duress-пароль дают
**разные** ключи, и слоты друг о друге не знают. Раскрытие одного salt'а
не помогает расшифровать другой слот.

### Заголовок контейнера

Всего 8 байт:

#@#
Offset  Size  Field         Value / Notes
------  ----  ------------  ------------------------------------------
0       4     magic         0x0BADC0DE (BE u32)
4       2     version       0x0002 (BE u16)
6       1     slot_count    1 или 2
7       1     pad           0x00
#@#

- `magic` — сигнатура формата. Если не совпадает → `bad magic`.
- `version` — версия формата. Сейчас только `2`. Если встретится другая →
  `unsupported version N`.
- `slot_count` — 1 (без duress) или 2 (с duress). Больше 2 запрещено
  (`MAX_SLOTS = 2`).
- `pad` — выравнивание до 8 байт. Всегда `0x00`.

### Слот

#@#
Offset  Size         Field         Notes
------  -----------  ------------  ------------------------------------
0       16           salt          Argon2id salt
16      8            slot_len      BE u64, длина slot_body
24      slot_len     slot_body     см. «Зашифрованный поток»
#@#

`salt` — 16 случайных байт из `rand::thread_rng()`. Генерируется заново
для каждого слота при каждом `--lock`.

`slot_len` — длина зашифрованного потока в байтах. Позволяет пропустить
слот, не расшифровывая его целиком.

`slot_body` — см. следующий раздел.

### Внутренний поток (plaintext)

Это то, что кладётся **до сжатия и шифрования**. Единый поток байт,
последовательная запись:

#@#
┌──────────────────────────────────────────────────────────┐
│ Inner Header                                             │
│   ├── version       (2 bytes, BE u16)   = 0x0002         │
│   ├── dirname_len   (4 bytes, BE u32)                    │
│   ├── dirname       (dirname_len bytes, UTF-8)           │
│   ├── reserved      (64 bytes, все нули — legacy SHA-512)│
│   └── magic         (4 bytes, BE u32)   = 0x0BADC0DE     │
├──────────────────────────────────────────────────────────┤
│ Entry 0                                                  │
│   ├── path_len      (4 bytes, BE u32)                    │
│   ├── path          (path_len bytes, UTF-8, /-разделители)│
│   ├── size          (8 bytes, BE u64)                    │
│   └── content       (size bytes)                         │
├──────────────────────────────────────────────────────────┤
│ Entry 1                                                  │
│   ...                                                    │
├──────────────────────────────────────────────────────────┤
│ ...                                                      │
└──────────────────────────────────────────────────────────┘
#@#

- `dirname` — базовое имя исходной директории (без пути). Например,
  для `--lock ./mydir` это `mydir`. Именно оно создаётся при распаковке
  в целевой директории.
- `reserved` — 64 байта, оставшиеся от legacy-формата, где сюда писался
  SHA-512 от всего плейнтекста. Сейчас **не заполняется** и **не проверяется**.
  Зарезервировано под будущее использование.
- Пути внутри архива нормализуются: `\` → `/`, префикс `./` убирается.
  Порядок записей — лексикографический (обеспечивается сортировкой в `pack`).
- Пустые директории **не сохраняются** — только файлы. При распаковке
  создаются только те директории, которые нужны для файлов.

Максимальные длины (см. `format.rs`):

#@#
MAX_DIR_NAME_LEN  = 255
MAX_PATH_LEN      = 4096
MAX_FILE_SIZE     = 10 GiB
#@#

### Зашифрованный поток (ciphertext)

`slot_body` — это `zstd(plaintext)` зашифрованный `ChaCha20-Poly1305`
чанками. Формат потока:

#@#
┌──────────────────────────────────────────────────────────┐
│ Chunk 0                                                  │
│   ├── plain_len   (4 bytes, BE u32)                      │
│   ├── nonce       (12 bytes, random)                     │
│   └── ciphertext  (plain_len + 16 bytes)                 │
├──────────────────────────────────────────────────────────┤
│ Chunk 1                                                  │
│   ...                                                    │
├──────────────────────────────────────────────────────────┤
│ ...                                                      │
└──────────────────────────────────────────────────────────┘
#@#

- `plain_len` — длина **плейнтекста** чанка (до шифрования), не считая
  Poly1305-тега. Считается по zstd-выхлопу.
- `nonce` — 12 случайных байт из `rand::thread_rng()`, генерируется заново
  для каждого чанка. **Не** инкрементный счётчик — именно random, что
  исключает nonce-reuse при параллельной/прерванной записи.
- `ciphertext` = `ChaCha20(plain) || Poly1305(tag)`, ровно `plain_len + 16` байт.

Длина чанка (`plain_len`) ограничена снизу `16 MiB`, сверху — `chunk_size`,
который выбирается при `--lock` как `min(1 GiB, max(16 MiB, MemAvailable/4))`.
Последний чанк может быть короче.

**Важно:** между `ChunkedWriter` (шифрование) и `zstd` нет явного согласования
границ. `zstd::Encoder` пишет произвольными порциями, `ChunkedWriter` буферизует
их и нарезает по `chunk_size`. То есть один zstd-фрейм может пересекать
несколько AEAD-чанков — это нормально, `ChunkedReader` на чтении восстанавливает
непрерывный поток.

### Разметка байтов: пример

Маленький vault с одним файлом `a.txt` (5 байт: `hello`), без duress,
`chunk_size = 16 MiB`:

#@#
0000  0B AD C0 DE              magic
0004  00 02                    version = 2
0006  01                       slot_count = 1
0007  00                       pad
0008  <16 bytes salt>           slot 0 salt
0018  <8 bytes slot_len>        slot 0 length
0020  <slot 0 body>:
        00 00 00 0A            plain_len = 10 (zstd-фрейм)
        <12 bytes nonce>
        <10 bytes ciphertext>
        <16 bytes Poly1305 tag>
#@#

Внутренний plaintext (после расшифровки и распаковки zstd):

#@#
00 02                          version = 2
00 00 00 05                    dirname_len = 5
6D 79 64 69 72                 "mydir"
<64 bytes нулей>               reserved (legacy SHA-512)
0B AD C0 DE                    magic
00 00 00 05                    path_len = 5
61 2E 74 78 74                 "a.txt"
00 00 00 00 00 00 00 05        size = 5
68 65 6C 6C 6F                 "hello"
#@#

## Криптография

### Argon2id

Параметры (жёстко зашиты в `argon.rs`):

#@#
Algorithm:     Argon2id
Memory:        64 MiB  (65536 KiB)
Iterations:    3
Parallelism:   2
Salt:          16 bytes
Output:        32 bytes (256-bit key)
#@#

Salt уникален для каждого слота при каждом `--lock`. Один и тот же пароль
с разными salt'ами даёт разные ключи.

Время деривации ключа: ~0.5–1.5 сек на современном CPU (зависит от железа).
Именно поэтому перебор 2 слотов при неверном пароле стоит ~2× Argon2.

### ChaCha20-Poly1305

Используется **XChaCha20-Poly1305** (расширенный nonce, 24 байта) в
некоторых сборках или стандартный ChaCha20-Poly1305 (12 байт) — в зависимости
от версии `chacha20poly1305`. Актуальный размер nonce смотри в `chunks.rs`:
`NONCE_SIZE` — источник истины.

Свойства:
- AEAD: шифрование + аутентификация. Любое изменение ciphertext → tag mismatch.
- 12/24-байтовый nonce, генерируется случайно для каждого чанка.
- Тег — 16 байт Poly1305.

### Размеры и лимиты

| Параметр | Значение |
|---|---|
| Salt size | 16 байт |
| Key size | 32 байта |
| Nonce size | 12 или 24 байта (см. `chunks.rs`) |
| Poly1305 tag | 16 байт |
| Min chunk size | 16 MiB |
| Max chunk size | 1 GiB |
| Default chunk size | `MemAvailable/4`, clamp [16 MiB, 1 GiB] |
| Max slots | 2 |
| Max file size | 10 GiB |
| Max path length | 4096 |
| Max dirname length | 255 |
| Container header | 8 байт |

## Wipe и уничтожение

`FalkonR` затирает:

1. **Исходную директорию** после успешного `--lock` — все файлы
   перезаписываются 3 проходами (случайные байты, случайные байты, нули),
   затем `fsync` и `remove`.
2. **Vault-файл** при duress-разблокировке — параллельная перезапись
   (несколько потоков пишут случайные чанки + параллельные bit flips по
   всему файлу), затем `fsync` и `remove`.

### Важное предупреждение

На **NVMe/SSD** и **CoW-файловых системах** (btrfs, ZFS, APFS) физическое
затирание **не гарантировано**:

- **SSD/NVMe**: wear leveling, SLC-кеш, over-provisioning, скрытые блоки.
  Перезапись LBA ≠ перезапись физических ячеек.
- **btrfs/ZFS/APFS**: copy-on-write, снапшоты, checksums, compression.
  Перезапись файла создаёт новые экстенты, старые остаются.
- **Page cache и journal**: часть «перезаписей» может не дойти до диска
  при внезапном отключении питания.

Что **реально** работает:

- **Логическое уничтожение.** AEAD-тег ломается от одного изменённого байта.
  Vault становится нерасшифровываемым, даже если физически не затёрт.
  Этого достаточно в 99% угроз (атакующий без физического доступа к носителю).
- **FDE + выброс ключа.** LUKS на весь диск, `cryptsetup luksErase` стирает
  мастер-ключ — данные восстановить невозможно. Единственный способ
  гарантированного уничтожения на SSD/CoW.
- **`nvme format` / `nvme sanitize`.** Стирает весь NVMe целиком.

Для гарантированного уничтожения на NVMe + btrfs используй полное шифрование
диска и уничтожай мастер-ключ LUKS, а не полагайся на wipe файла.

## Ограничения

- **Только Linux.** Используется `mlock`/`munlock` через `libc`, `/proc/meminfo`
  для определения размера чанка, `tokio::signal` для Ctrl+C.
- **Нет частичного восстановления.** Vault — монолитный поток. Нельзя
  распаковать один файл, не расшифровав всё до него.
- **Нет incremental backup.** Каждый `--lock` создаёт vault с нуля.
- **Нет сжатия на уровне отдельных файлов.** zstd работает по всему потоку.
- **Пустые директории теряются.** Сохраняются только файлы.
- **Права и владельцы не сохраняются.** При распаковке файлы создаются
  с `0600`, директории — `0700`. Метаданные (`mtime`, `uid`, `gid`, xattr)
  не пишутся.
- **Legacy-поле `reserved`** (64 байта) не используется. Оставлено для
  совместимости с оригинальным Go-форматом и под будущее.
- **`--duress <argv>` устарел.** Не используй. Duress теперь задаётся
  интерактивно при `--lock` и хранится в отдельном слоте.

## Сборка

Требования:
- Rust stable ≥ 1.75
- Linux (x86_64 или aarch64)

#@#
cargo build --release
#@#

Бинарник: `target/release/FalkonR`.
